# 18. AI 여행 어시스턴트 (AI Travel Assistant)

> 워크스페이스 안에서 대화로 장소를 **추천받고 → 실제 일정에 반영**하는 어시스턴트.
> 한 어시스턴트가 "이 도시 카페 3곳 추천해줘"(추천)와 "도쿄 2일 코스 짜줘"(코스 설계)를 모두 처리한다.
> 기법: **RAG**(여행 데이터 근거) + **Places grounding**(실존 장소·좌표) + **툴콜**(에이전트가 앱 기능 실행).
> 기존 화면·플로우에 **additive** — 어시스턴트를 열지 않으면 04~07 동작은 완전히 동일하다.
>
> **상태**: GATE 1 ✅ 승인(2026-07-31) · GATE 2 ✅ 승인 · 구현 **phase 1~5 완료**(#31~#35).
> 설계와 달라진 점·남은 갭은 `docs/architecture/AI_어시스턴트_설계.md` **§13.1 · GATE 상태** 참고.

## 1. 화면 목적

- 사용자가 **자연어로 묻고**, 어시스턴트가 **이 여행의 맥락**(도시·날짜·이미 담은 장소·예산·카테고리 편중)을 근거로 답한다.
- 추천 결과는 **실존 장소 카드**(이름·카테고리·좌표·주소)로 나오고, 그대로 **저장 / 일정 반영 / 코스 적용**까지 이어진다.
- "추천만 하고 끝"이 아니라 **추천 → 실행(일정 배정) → 동선 최적화**까지 한 흐름으로 잇는 것이 핵심.

### 1.1 대응하는 두 가지 의도

| 의도 | 예시 발화 | 결과 |
|---|---|---|
| **장소 추천** | "이 근처 조용한 카페 3곳", "아이랑 갈 만한 곳" | 장소 카드 N개 + 각 카드 "저장"/"Day N에 추가" |
| **코스 설계** | "도쿄 2일 코스 짜줘", "Day 2 오후 비어 있는데 채워줘" | Day별 순서가 있는 코스 제안 + "코스 적용"(일괄 반영 → 동선 최적화 제안) |

두 의도는 **한 대화 안에서** 처리된다(별도 화면/모드 없음). 어떤 도구를 쓸지는 모델이 결정한다(§5).

## 2. 사용자 · 진입 경로

- **진입**: 워크스페이스(`/trips/[id]`) 우하단 **플로팅 액션 버튼(FAB)** → **어시스턴트 패널**(데스크톱: 우측 392px 사이드 패널 / 모바일: 바텀시트).
- **가용 뷰**: `?view=plan`·`?view=places` (일정·장소 맥락이 있는 뷰). `calendar`·`budget`·`stats` 에서는 FAB 미노출(1차 범위).
- **권한**:
  - `owner`/`editor` — 대화 + **실행(저장·일정 반영·코스 적용)** 전부.
  - `viewer` — 대화·추천 **조회만**. 실행 버튼 미노출 + 서버에서 거부(RLS `place` write = editor+).
  - **공유 뷰어(`/share/[token]`)** — 어시스턴트 **미제공**(비로그인·토큰 스코프. LLM 호출 남용 방지, §6).

## 4. 데이터 · 상태

### 4.1 어시스턴트가 참조하는 근거 (RAG)

| 근거 | 출처 | 용도 |
|---|---|---|
| 여행 메타 | `trip`(제목·기간·나라/지역·base_currency) | "언제·어디" 맥락 |
| 도시 | `trip_city`(name·nights·seq) | 다중 도시 시 "이 도시" 해석 |
| 담은 장소 | `place`(name·category·area·scheduled_date·lat/lng) — **`memo` 제외** | 중복 추천 방지, 취향 추론 |
| 일정 밀도 | `place` × Day 집계 | "Day 2 비어 있음" 판단 |
| **의미 검색** | `place` 임베딩(pgvector) | "조용한", "분위기 좋은" 같은 **의미 기반** 유사 장소 검색 |

- **임베딩 대상**: 이 여행(및 사용자 접근 가능 범위)의 `place` 텍스트(`name` + `category` + `area`).
- **왜 필요한가**: 키워드 매칭으로는 "이미 담은 곳과 비슷한 분위기"·"조용한 곳" 같은 질의를 못 푼다. 담은 장소를 벡터로 두면 **취향 근거**를 만들 수 있다.
- **⚠️ `memo` 는 제외한다**(설계 확정, 계약 C2-b): 자유 입력이라 예약번호·동행자 실명 같은 개인정보가 섞일 수 있고, 임베딩은 **외부 provider 로 전송**되기 때문이다. 채팅 컨텍스트에서도 마찬가지로 보내지 않는다 — 한쪽만 막으면 의미가 없다. 그만큼 취향 추론은 이름·카테고리·지역 수준으로 제한되지만, 추천의 실체는 Places grounding 이 담당하므로 기능은 성립한다. (후속에 여행별 opt-in 으로 확장 여지)

### 4.2 대화 상태

- **대화 세션**: MVP는 **비영속(메모리)** — 패널을 닫으면 사라진다. `trip_id` 단위 클라이언트 상태.
  - 이유: 대화 로그 영속화는 PII·보관정책 이슈를 동반한다(§8.5). **영속 저장은 후속**(§8 후속 항목).
- **서버 상태**(TanStack Query): 추천이 만든 `place` 변경은 **기존 `['places', tripId]` 캐시**를 그대로 무효화 → 지도·일정·장소 뷰가 자동 갱신(신규 상태 경계 없음).
- **사용량**: 사용자·여행별 요청 카운터(rate limit, §6) — 서버 판정, 클라는 잔여 표시만.

## 5. 인터랙션 (플로우)

### 5.1 장소 추천

1. 사용자: "이 근처 조용한 카페 3곳 추천해줘" → 전송.
2. 서버: 세션·멤버십 검증 → 여행 컨텍스트 조립(§4.1) + **pgvector 유사 장소 검색**.
3. 모델이 **`searchPlaces` 도구**를 호출 → **Google Places** 로 실존 장소 조회(이름·좌표·주소·place_id).
4. 답변이 **스트리밍**되며, 도구 결과는 **장소 카드**로 렌더(좌표 없는 후보는 카드에서 제외).
5. 사용자가 카드에서 `저장` 또는 `Day N에 추가` → 기존 뮤테이션(`useUpsertPlace` / `useAddPlaceToSchedule`) 실행 → 지도·일정 즉시 갱신.
6. 근거 칩에 "담은 장소 12곳 참고" 표기.

### 5.2 코스 설계 → 실행 → 동선 최적화

1. 사용자: "Day 2 오후 비었는데 채워줘".
2. 모델: 여행 컨텍스트로 Day 2 기존 일정 파악 → `searchPlaces` 로 후보 확보 → **구조화 출력**(장소 + 순서)으로 코스 제안.
3. 코스 블록 표시(시안 H): Day별 번호 타임라인 + 헤더 메타("5곳 · 도보 위주").
4. **`코스 적용`** 클릭 → 확인 다이얼로그("Day 2에 3곳을 추가합니다") → 일괄 배정(부분 실패 시 성공분 유지 + 실패 안내).
5. **`동선 최적화`** — 시안상 코스 블록 **푸터의 두 번째 버튼**이다(적용 후 별도 제안 배너가 아니다). 누르면 기존 동선 최적화(`useRouteOptimize`) 미리보기로 연결(16번 기능 재사용).
   - 적용 **전**에 누르면: 제안된 코스 순서를 대상으로 미리보기(아직 저장 안 함).
   - 적용 **후**에 누르면: 그 Day 의 실제 일정을 대상으로 기존 플로우 그대로.
6. **되돌리기**: 적용 직후 "방금 추가한 3곳 되돌리기"(추가된 place 배정 해제).
7. **`다시 제안`**(시안 I): 같은 질문으로 코스를 재생성(rate limit 1회 소비).

### 5.3 취소 · 중단

- 스트리밍 중 **중지** 버튼 → 요청 abort(부분 답변 유지, 도구 실행분은 이미 반영된 것만).

## 6. 제약 · 엣지 케이스

| 상황 | 처리 |
|---|---|
| **환각(존재하지 않는 장소)** | LLM 단독 장소 추천 **금지**. 카드에 뜨는 장소는 **Places 조회로 검증된 것만**(좌표·place_id 확보). 검증 실패한 이름은 본문 텍스트로만 남기고 카드/액션 미제공 |
| **좌표 없는 추천** | 카드에서 제외(또는 "위치 미확인" 배지 + 액션 비활성). 일정 반영은 좌표 있는 것만 |
| **LLM 키 없음 / 미설정** | FAB 미노출. 기존 화면 100% 정상 동작(feature flag, 회귀 0) |
| **LLM 호출 실패·타임아웃** | "지금은 답할 수 없어요. 잠시 후 다시 시도해주세요" + 재시도 버튼. 크래시 없음 |
| **Places 실패/쿼터** | 도구 결과 없음 → 모델이 "장소를 찾지 못했다"로 답하고 **가짜 장소를 만들지 않는다**(도구 실패는 근거 없음으로 취급) |
| **rate limit 초과** | "오늘 사용량을 다 썼어요(N/N)" — 입력 비활성 + 리셋 시각 안내 |
| **viewer 가 실행 시도** | 버튼 미노출 + 서버/RLS 거부. UI 숨김은 보안이 아님 |
| **프롬프트 인젝션** | 장소 메모 등 **사용자 데이터는 데이터로만** 취급(시스템 지시 오염 방지, 설계 §가드레일). 도구는 화이트리스트만 |
| **긴 대화 / 큰 여행** | 컨텍스트는 상위 K개 근거로 제한(토큰·비용), 대화는 최근 N턴만 전송 |
| **다중 도시** | "이 도시"는 현재 선택된 도시(`trip_city`) 기준으로 해석. 도시 미선택이면 되물음 |
| **비용 폭주** | 무료 티어 우선 + 요청당 도구 호출 상한 + 일일 상한(§설계 비용) |

### 7.1 viewer 화면 처리 (시안 확정)

시안은 viewer 에게 **"버튼만 사라진 화면"이 아니라 이유를 설명하는 화면**을 준다:

| 위치 | viewer 처리 |
|---|---|
| 패널 헤더 | **"뷰어" 배지** + 서브텍스트 **"대화만 가능해요"** |
| 추천 카드 | 액션 영역(`저장`·`일정에`) **미렌더** |
| 코스 블록 푸터 | 버튼 대신 안내 — **"읽기 전용 — 코스를 적용하려면 편집 권한이 필요해요"** |
| 빠른 질문 칩 | 실행형 제외, **`카페 추천`·`근처 맛집` 2개만** 노출 |

> UI 표현일 뿐 차단은 서버 — viewer 가 강제로 뮤테이션을 호출해도 `place` RLS 가 거부한다.

## 8. 라우팅 연결

- **별도 라우트 없음** — `/trips/[id]?view=plan|places` 내 오버레이 패널.
- 패널 개폐는 URL 파라미터로 남기지 않는다(뒤로가기 오염 방지). 로컬 UI 상태.
- 서버 엔드포인트(신규): `POST /api/assistant/chat` (스트리밍) — 화면 라우트 아님.

## 9. 구현 메모 (개략)

- `features/assistant/` 신규 도메인(components·hooks·api·types). 기존 도메인 침범 없음.
- 실행 도구는 **기존 훅 재사용**: `useUpsertPlace`, `useAddPlaceToSchedule`, `useRouteOptimize`, `lib/route/*`.
- 상세는 `docs/architecture/AI_어시스턴트_설계.md`.

## 11. 수용 기준 (검증 체크리스트)

> 표기: **[x]** 자동 테스트로 검증됨 · **[~]** 부분 충족(사유 명시) · **[ ]** 미충족·미검증.
> 근거는 `src/**/*.test.*`(Vitest)와 `e2e/assistant.spec.ts`(Playwright, 실 Supabase).

**기능**
- [x] 플랜/장소 뷰에서 FAB → 패널이 열리고, 질문 전송 시 답변이 **스트리밍**으로 표시된다. — e2e 1·2
- [~] "카페 3곳 추천" 류 질의에 **실존 장소 카드**(이름·카테고리·주소·좌표)가 3개 이상 표시된다.
      → 카드 렌더·grounding 은 검증(도구 상한 5건). **"3개 이상"은 실 Places 키로만 확인 가능해 미검증**
- [x] 카드의 `저장` → 장소 뷰 목록에 나타난다(`['places']` 갱신). — `useUpsertPlace` payload·무효화 검증(단위)
- [~] 카드의 `Day N에 추가` → 해당 Day 일정·지도 마커·번호가 갱신된다.
      → `assign(placeId, day)` 호출·순서 검증(단위). 카드 경로의 지도 반영은 **코스 적용 e2e로 간접 확인**
- [x] "2일 코스 짜줘" 류 질의에 **Day별 순서가 있는 코스**가 제안되고, `코스 적용`으로 일괄 반영된다. — e2e
- [~] 코스 적용 직후 **동선 최적화 제안**이 노출되고, 수락 시 기존 최적화 미리보기로 이어진다.
      → 버튼 노출은 e2e 검증. **수락 후 미리보기 표시는 미검증**(좌표·Directions 필요)
- [x] 적용 직후 **되돌리기**로 방금 추가된 장소가 일정에서 사라진다. — e2e (구현은 생성 행 **삭제**, 설계 §13.1-5)
- [x] 답변에 **근거 칩**(참고한 여행 데이터)이 표시된다. — 단위 + e2e
- [ ] 실패 시 **재시도** 버튼으로 복구된다. → `MessageActions` **미구현**. 안내 문구만 표시(설계 GATE 상태)

**안전·권한**
- [x] `viewer` 는 실행 버튼이 보이지 않는다. — 단위 + e2e(실제 역할을 viewer 로 낮춰 검증)
- [~] `viewer` 가 강제로 호출해도 서버가 거부한다. → `place` RLS(`editor+`)가 강제하나 **어시스턴트 경로 전용 회귀 테스트는 없다**
- [x] 공유 링크(`/share/[token]`)에는 어시스턴트가 없다. — `AssistantLauncher` 는 `WorkspaceShell`(=`/trips/[id]`)에만 마운트
- [x] 좌표가 확보되지 않은 추천은 카드/일정 반영 대상에서 제외된다(환각 차단). — 스키마·도구·패널 3중 검증
- [x] LLM 키 미설정 환경에서 FAB 이 뜨지 않고 **기존 화면·테스트가 전부 그대로 통과**한다(회귀 0). — 라우트 503 + 런처 미노출
- [x] LLM/Places 실패 시 **안내가 뜨고 앱이 죽지 않는다**. — 502·스트림 중단·빈 결과 폴백 검증
- [x] rate limit 초과 시 안내가 뜨고 추가 호출이 차단된다. — 429 + 입력·칩 비활성 + 리셋 시각(단위 + e2e)
- [x] 클라이언트 번들·네트워크 응답 어디에도 **LLM/임베딩 API 키가 노출되지 않는다**. — `NEXT_PUBLIC_` 미사용 + 빌드 산출물 검사
- [x] 장소 **메모(`memo`)가 LLM·임베딩 provider 로 전송되지 않는다**. — 쿼리에서 제외 + 컨텍스트·임베딩 원문 회귀 테스트

**시안 일치**
- [x] FAB 이 데스크톱은 **알약형("AI에게 묻기")**, 모바일은 **56px 원형**으로 뜨고, 패널이 열리면 숨는다.
- [x] 패널 폭 **392px**, 헤더에 아바타·제목·서브텍스트·닫기가 시안대로 배치된다. — e2e 로 폭 실측
- [x] 추천 카드에 **미니맵 썸네일 74×74** + 카테고리 pill + 주소가 표시된다.
- [ ] 코스 블록 푸터에 **`코스 적용` + `동선 최적화`** 두 버튼이 있다.
      → **의도적 이탈**: 적용 전에는 최적화 대상이 없어, `코스 적용` → 적용 후 `되돌리기`+`동선 최적화` 순차 노출(설계 §13.1-4)
- [x] `viewer` 는 헤더 "뷰어" 배지 + 코스 푸터 안내문 + 빠른 질문 칩 2개로 축소된다(§7.1).

**추가 확인(설계 §6.5 — 기획 작성 후 확정)**
- [x] 로그에 **API 키·프롬프트·사용자 메시지·PII 가 남지 않는다**. 허용 필드만 화이트리스트로 직렬화 — 캐스팅 우회까지 회귀 테스트

**비기능 한 줄**
기준 뷰포트 1280px(패널 392px, 좌측 일정 패널·지도와 겹침 없음) + 태블릿/모바일은 바텀시트로 대응. 접근성: 패널은 `role="dialog"` + 포커스 트랩 + Esc 닫기, 메시지 영역 `aria-live="polite"`, 스트리밍 텍스트는 스크린리더 중복 낭독 방지, 모든 액션 버튼 키보드 도달 가능. 로딩: 첫 토큰 3초 내 표시(미달 시 shimmer 유지), 도구 실행 중 진행 문구 노출.

## 12. 트리플·경쟁 서비스 대비 우위

| | 일반 여행앱 / 트리플 | jero(이 기능) |
|---|---|---|
| 추천 방식 | 에디터 큐레이션·인기순 고정 | **대화형 + 내 여행 맥락(RAG) 기반** |
| 근거 | 불투명 | **무엇을 보고 추천했는지 근거 칩으로 제시** |
| 실존성 | 자체 DB | **Google Places 검증**(좌표·place_id 확보, 환각 차단) |
| 결과 활용 | 읽고 수동 저장 | **툴콜로 일정에 바로 반영 + 동선 최적화까지 연결** |
| 코스 | 정적 추천 코스 | **내 날짜·이미 담은 곳을 반영한 동적 코스 설계** |

> 포트폴리오 관점: "LLM 붙였다"가 아니라 **RAG(pgvector) + grounding(Places) + tool calling(실제 뮤테이션 실행) + 가드레일·비용관리**를 한 기능에서 증명한다.
